## Verifikasi dan batas bukti

- Database tests memakai PGlite memory dengan seluruh migration files, tanpa koneksi ke Neon aktif. Fase 2–8 mencakup grant/role, subscription lifecycle, job/inbox, provider handler, settlement/unsettled, exception, financial request identity, WIB boundary, quota, runtime flags dan maintenance cleanup; total 80 lulus.
- Auth tests memakai secret sintetis; total 14 lulus. `pnpm test:auth:http` 20 assertion pada build terisolasi. `pnpm test:provider` 3 test HMAC. `pnpm test:observability` 4 test redaction/taxonomy/log. `pnpm test:env` 12 dan `pnpm test:dependencies` 3 lulus.
- Demo tests: 74 domain + 3 network-policy lulus; ini bukan provider, concurrency PostgreSQL lintas koneksi atau merchant production.
- Build memakai `scripts/build-isolated.mjs` yang mengarahkan DB dan provider ke loopback port tertutup. Fase 8–9 membangun Owner/POS/Superadmin/Landing pada `.next-hardening-phase89`; artefak bukan rilis deployment.
- Workflow CI menyiapkan PostgreSQL dua koneksi, tetapi belum dieksekusi di GitHub. Restore drill, alert delivery, PITR, credential rotation dan pilot acceptance belum dijalankan.
- Migrasi 0005–0014 hanya berkas. Tidak ada migration, seed, cleanup, deployment, email nyata atau transaksi provider yang dijalankan ke resource aktif.
- Hasil pemeriksaan akhir dan acceptance staging dicatat dalam `IMPLEMENTATION_PLAN.md`, `PHASE_1_REPORT.md`–`PHASE_9_REPORT.md`, `config/provider/README.md`, `config/settlement/README.md`, `config/operations/README.md` dan `config/pilot/README.md`; keputusan launch saat ini **NO-GO**.

## Reproduksi aman

Jalankan `pnpm test:auth`, `pnpm test:provider`, `pnpm test:observability`, `pnpm test:env`, `pnpm test:dependencies`, `pnpm test:db`, `pnpm test:demo` dan, hanya pada DB disposable, `RAKKU_ALLOW_DISPOSABLE_DB=1 TEST_DATABASE_URL=... pnpm test:concurrency`. Gunakan `pnpm ops:snapshot -- --check`, `pnpm ops:cleanup` (dry-run) dan `pnpm ops:restore-verify` hanya pada target terisolasi. Regression test mencakup forged tenant/assignment, paid order deletion, tampering nominal, replay request, session revocation, HPP snapshot, provider timeout/late success, RBAC, subscription request identity/state machine/journal, inbox/job/DLQ, settlement/unsettled, exception, financial request identity, WIB boundary, quota, runtime flag dan cleanup evidence. Harness dua koneksi belum dijalankan pada DB nyata. Jangan mengulang skenario ini menggunakan akun/data production.
